Result

On PEP/KO, the rolling hedge beat the Kalman hedge out of sample#

On the train window both hedges earned money: Sharpe 0.88 for rolling OLS and 0.45 for Kalman. In the test window the rolling hedge kept a 0.62 Sharpe and the Kalman hedge fell to −0.44, a gap of 1.06.[E1] The tuned settings were entry z 1.5, exit 0.5, 20-day window for OLS; entry 1.5, exit 0, delta 1e-05 for Kalman.

PEP/KO fails the Engle–Granger test on the train window (p = 0.18), so the spread is not shown to mean-revert; the app flags this, and the result is a model comparison on a weak pair, not evidence of a tradable edge.

Mechanism

The tuned Kalman hedge was too slow to follow the pair#

A Kalman filter treats the hedge ratio as a hidden value that drifts; delta sets how fast it may drift. Tuning picked the smallest delta in the grid, 1e-05, so the Kalman hedge behaves almost like one fixed ratio. The 20-day regression instead refits every day.

A slow hedge lets the spread inherit any lasting change in how the two stocks move together, so its z-score can stay stretched for months. The Kalman results — fewer, longer trades and a falling test equity — are consistent with that; this study does not isolate the cause.

Robustness

A one-day fill delay did not change which hedge won#

Filling at the signal's own close assumes the trade gets a price that was already used to decide it. Moving every fill one close later changed the rolling hedge's Sharpe from 0.62 to 0.77 and Kalman's from −0.44 to −0.52, so same-close fills do not explain the ranking.[E3]

The rolling hedge's own level is fragile: it turned negative in 1 setting — next-day fills at 5 bp (−0.28, train 0.14) — and its test Sharpe does not fall steadily with cost, because each cost re-tunes the parameters on a short train window.

Pair scan

The scanner screens 55 pairs and corrects for multiple testing#

At 5% per test, 55 independent tests would give about 2.8 false hits by chance; the screen found 4. Benjamini–Hochberg keeps the expected share of false discoveries at 5% and, on this universe and period, keeps 0. The scanner reports that instead of a ranked list of likely false positives.

App

The Streamlit app runs the same code on any two tickers#

Settings sit in the sidebar: tickers, dates, train share, thresholds and costs. The pair scanner tab runs the same Benjamini–Hochberg screen on any ticker list. Screenshots are from an earlier commit with the same defaults.

Methodology#

Data
Yahoo Finance via yfinance, auto_adjust=True (split- and dividend-adjusted closes); PEP/KO and 9 more tickers, 2018-01-02 to 2024-12-30 (1,760 days), fetched 2026-11-23, committed as data/prices.csv[E9]
Split
Warm-up 60 days from 2018-01-02; train 2018-03-29 to 2022-03-11; test 2022-03-14 to 2024-12-30
Tuning
Grid search on train-window Sharpe: 24 configurations for Kalman, 24 for rolling OLS; no adjustment for the number of configurations
Signal
z-score of the model's prediction error; enter beyond the entry threshold, exit back toward zero
Sizing
Gross exposure equal to account equity, $100,000 start, long one leg and short the other
Costs
1 bp commission + 1 bp slippage per fill on traded notional; sweep 0–20 bp[E5]
Fills
Default at the signal's close; also one close later (fill_lag=1)[E4]
Sharpe
Daily returns × √252, risk-free rate 0; standard error ≈ √((1 + SR²/2) / years)
Not modelled
Borrow fees, margin interest, market impact, partial fills

Limitations

Results cover one pair, one window and daily closes#

  • One pair, one period. The ranking is measured on PEP/KO in 2022–2024 only; another pair or period may reverse it.
  • Short test window. 2.8 years gives a Sharpe standard error near ±0.65, so neither model's test Sharpe is distinguishable from zero.
  • Weak pair. PEP/KO fails Engle–Granger on the train window (p = 0.18) and the BH screen.
  • Tuning on a small grid. The best of 24 configurations is chosen per model with no multiple-testing adjustment; train Sharpe overstates what tuning buys.
  • Daily closes. Fills at a close, at most one day late; no intraday prices, impact or borrow costs.
  • Adjusted prices change. Yahoo revises adjusted closes after each dividend; the committed snapshot fixes them, a fresh download will differ slightly.

Reproduce

Reproduce it from the committed prices#

Commands run from a clone of allenwang0/statarb.

  1. Install (Python 3.11 or 3.12) and run the tests.

    python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/pytest -q

  2. Re-run the case study from the committed prices (about 11 s); results/case_study.json should not change. Add --fetch to re-download (network; adjusted prices will differ slightly).

    .venv/bin/python scripts/case_study.py
git diff --exit-code results/case_study.json

  3. Rebuild this page and the README block (Python standard library only).

    python3 scripts/build_report.py --readme README.md

  4. Open the app.

    .venv/bin/streamlit run app.py
